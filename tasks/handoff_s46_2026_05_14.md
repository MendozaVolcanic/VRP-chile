## ⭐ Hallazgo MAYOR S45: cluster selection MIROVA es summit-priority (D1+D2+D5)

**Refutamos** la hipótesis "MIROVA reporta múltiples clusters por timestamp":
OSF v2.5 muestra 1 alerta por (volcán, ts, sensor) en 10,579/10,579 filas Chile.

**Refutamos** "MIROVA elige max-VRP global": caso PCC 2026-05-09 muestra
cráter 4.94 MW perdiendo contra lacolito 0.18 MW.

**Confirmamos** triangulando 3 evidencias:
1. Paper Coppola 2016a Table 2: dual-ROI summit C1=0.003 más permisivo que
   scene C1=0.010 (no documenta selección, lo deja implícito).
2. OSF v2.5 empírico: 1 alerta/scene contradice multi-cluster.
3. **Lascar 4 FN MODIS pixel-level**: nuestro `anomaly_pixels` SÍ contiene
   el píxel cráter (BT 272-274 K @ 0.6-2.4 km, vrp 1.3-1.9 MW) pero queda
   sepultado entre 75-83 píxeles más calientes del Salar de Atacama
   (BT 278-283 K @ 18-30 km W). Nuestro clustering elige Salar. MIROVA en
   cambio reporta el píxel cráter.

**Conclusión**: MIROVA evalúa el ROI summit (5×5 km) **separadamente** del
scene. Si summit dispara con su umbral permisivo, MIROVA reporta ESA alerta
ignorando scene-wide.

**Lógica propuesta** (en `pipeline/store.py` o `clustering.py`):
```python
# Si hay pixel(es) dentro de inner_radius_km con BT > t_bg + 2σ,
# construir primary_cluster SOLO con esos pixels (ignore scene-wide max)
def select_primary_cluster_summit_priority(record, inner_radius_km, sigma_factor=2.0):
    summit_pixels = [p for p in record['anomaly_pixels']
                     if p['dist_km'] <= inner_radius_km
                     and p['bt_k'] > record['t_bg_k'] + sigma_factor * record['diag_sigma_bg_k']]
    if summit_pixels:
        # Cluster summit-only
        return build_cluster(summit_pixels)
    # Fallback to existing vent_anchored / cluster_hotspots
    return record['primary_cluster']
```

## Errores metodológicos S45 (DOCUMENTAR + INTERNALIZAR)

### 1. Asumí TIFs disponibles sin verificar archive retention

Empecé R2 pixel-level FN Lascar antes de verificar que mirova-tif-archive
tuviera los TIFs de 04-27 a 04-30. Solo tenía 05-08+. Pivoted a Plan B
(análisis pixel-level nuestro lado) tras descubrir el gap. Costo: ~10 min.

**Regla S46+**: ANTES de proponer R2 pixel-level vs TIF MIROVA, verificar
disponibilidad: `cat mirova-tif-archive/index.csv | grep <volcano>_<sensor>`
y confirmar rango de fechas cubre el target.

### 2. Window 15d en handoff S44 era ficticio

Handoff afirmaba "recall 94.8% window 2026-04-27→2026-05-11" pero CSV
consolidado termina 2026-05-01. Mi audit corregido sobre window real
(5 días efectivos) dio recall 85.4%, no 94.8%. Las métricas S44 anexadas
al handoff probablemente usaron tolerancia más laxa o datos no
verificables.

**Regla S46+**: cualquier afirmación de métrica DEBE incluir window real
verificable contra ground truth disponible. Si el CSV ground truth termina
X, no afirmar métricas hasta X+N.

### 3. Audit Python inicial con schema gap

Primer intento usó `r.get('timestamp_utc')` cuando el schema real usa
`r.get('datetime_utc')`. TP=0 global. Bug detectado tras 1 ronda. Costo:
~5 min.

**Regla S46+**: ANTES de audit Python complejo, hacer una pasada de
diagnóstico estructural sobre 1 record:
```python
d = json.loads(...); r = d['records'][0]; print(list(r.keys()))
```
