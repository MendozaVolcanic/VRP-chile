## Lectura física

El bug D8 (Puyehue lacolito reportado como cráter, Lascar Salar como
primary) **NO es de detección** — el lacolito y el cráter sí se
detectan. Es de **cluster selection**: nuestro pipeline elige el
cluster con mayor `vrp_mw` (típicamente el más grande, no el más
relevante volcanológicamente). MIROVA implícitamente prioriza
cluster vent-anchored.

H_D8_5 paper-puro abordó detección — capa equivocada del problema.

## Plan S38 — Cluster selection vent-anchored (verdadero fix D8)

H_D8_5 mostró que detección está cubierta. La capa que falla es selection.
Hipótesis: cambiar `clusters.sort(key=vrp_mw, reverse=True)` por una
prioridad que matchea MIROVA.

### Diseño preliminar

En `pipeline/clustering.py:99-101` cambiar el sort por:

```python
# Opción A — proximity-only:
clusters.sort(key=lambda c: c["centroid_dist_km"])

# Opción B — proximity priority pero filtro vrp_mw > 0:
def vent_anchored_key(c):
    inside_inner = c["centroid_dist_km"] <= inner_radius_km
    # Clusters dentro del inner_radius primero (más cercano gana),
    # luego clusters fuera ordenados por VRP descendente
    return (0 if inside_inner else 1, c["centroid_dist_km"], -c["vrp_mw"])
clusters.sort(key=vent_anchored_key)

# Opción C — dual priority distance + magnitude:
# clusters.sort(key=lambda c: c["centroid_dist_km"] * (1 / max(c["vrp_mw"], 0.01)))
```

## Riesgo identificado pre-A/B

`compute_eti_scene_quadratic` puede ser **lento sobre granules grandes**
(VIIRS 375m granules tienen ~6500×4500 px). `np.polyfit` orden 2 es O(n)
pero con iterative re-fit hace 3 passes. Si granules grandes timeout,
hay que:
- O hacer subsample de pixels válidos para el polyfit (suficientemente
  representativo).
- O aumentar timeout-minutes del workflow.
- Observar el time de los jobs A/B; si >30 min por job, optimizar.
